# Scripting and Advanced Programming (`System/Script Code`)

The **`System/Script Code`** node provides an imperative algorithmic execution environment (Python and Lua) to process data, evaluate continuous kinematics, and synthesise ASS override tags or vector paths.
It documents the node topology, injected namespaces, the native replacement function catalogue, and the deterministic `by` dispatcher.

---

## 1. Node Topology, Ports, and Data Flow

```
┌─────────────────────────────────────────────────────────────┐
│ System/Script Code                   [ Language: Python v ] │
├─────────────────────────────────────────────────────────────┤
│ (o) [0] Loop In                             [0] Loop Out (o)│
│ (o) [1] In1                                   [1] Result (o)│
│ (o) [2] In2                                     [2] Out1 (o)│
│ (o) [3] In3                                     [3] Out2 (o)│
├─────────────────────────────────────────────────────────────┤
│ Inputs Count: [ 2                                         ] │
│ Script Editor: [ Ace Code Editor                          ] │
└─────────────────────────────────────────────────────────────┘
```

### 1.1. Input Ports (*Inputs*)
1. **`[0] Loop In` (Control / Context):** Receives the active iteration stream (`line`, `syl`, `word`, `char`, `MaxLoop`, `Slicer`). It grants the script direct access to the temporal and metric context of the current unit, preserving the execution chain towards the `System/Output` node.
2. **`[1] In1`, `[2] In2`, ..., `[N] InN` (Data):** Configurable dynamic inputs (from 1 up to 16). Exposed inside the script as global variables `in1`, `in2`, ..., `inN` (or matching the upstream wire name). If an input port is unplugged, it takes the value typed into the node's inline text widget.

### 1.2. Output Ports (*Outputs*)
1. **`[0] Loop Out` (Control / Context):** Forwards the enriched iterative context. Any ASS tags or variables generated by the script travel through this port to downstream nodes or to `System/Output`.
2. **`[1] Result` (String / Data):** Emits the primary script output (the value assigned to the `result` variable or the value returned by the last expression).
3. **`[2] Out1` ... `[N] OutN` (Optional Sub-outputs):** Exposed dynamically when the script assigns values to the `outputs` dictionary (in Python: `outputs['out1'] = ...` or `out1 = ...`; in Lua: `outputs.out1 = ...` or `out1 = ...`).

### 1.3. Body Properties (*Properties*)
1. **`language` (`Language`):** Execution engine selector: `"Python"` or `"Lua"`.
   * **Canonical Typing:** **Type C (Literal selector)**.
2. **`inputs_count` (`Inputs Count`):** Number of dynamic input slots exposed (1 to 16).
   * **Canonical Typing:** **Type C (Integer)**.
3. **`script` (`Script Code`):** Executable source code block.
   * **Canonical Typing:** **Type A (Evaluated and AST-validated source code)**.

## 2. Execution Lifecycle and Syntactic Preprocessing

### 2.1. Result Injection and Automatic Tag Merging
The final output of the script is resolved via two pathways:
1. **Explicit assignment:** By assigning to the `result = ...` variable (in Python or Lua).
2. **Last evaluated expression:** If the trailing line of the script is a bare expression (e.g. `pos(syl.x, syl.y) + fscxy(120)`), the engine automatically captures and assigns its evaluation to `result`.

> [!IMPORTANT]
> **Seamless ASS Tag Merging:** Whenever the string returned in `result` contains ASS tag syntax (`\` or `{...}`), Pyxis automatically merges it into `context["loop_tags"]` via the `merge_ass_tags` engine. This eliminates the need to route wires into manual tag combiner nodes: returning tags from your script directly embeds them into the final dialogue line produced by `System/Output`.

### 2.2. Mixed Output: Tags + Vector Shapes or Text in 'result'

What happens when the script simultaneously emits tags and printable content (e.g. `result = f"{{{pos(syl.x, syl.y)}\\p1}}{shape_star()}"` or `result = "{\\c&HFF&}Text"`)?

The engine's behaviour depends on the connection topology leading to `System/Output`:

1. **If the Script Code node is only routed through the loop stream (`Loop In` $\to$ `Loop Out`) without wiring `Result`:**
   * Pyxis detects the `\` or `{` characters and attempts to merge the string into `context["loop_tags"]` via `merge_ass_tags`.
   * `merge_ass_tags` isolates blocks within `{...}` for the tag header, but **does not replace the printable body content of the line**.
   * The `Return` port of `System/Output` (which defaults to the original syllable text `syl.text_stripped`) continues to govern the line's visual text or drawing, and any vector shape returned outside braces in `result` will not override the syllable text.

2. **If the `Result` wire is connected to the `Return` port (port 5) of `System/Output`:**
   * The complete composite string flows directly into the final rendering pipeline.
   * `System/Output` evaluates the input via **`evaluate_ass_line_tag_blocks()`**:
     - Identifies the presence of `\p1` or ASSdraw commands (`m `, `l `, `b `, etc.).
     - Validates, cleans, and merges tag blocks `{...}` safely.
     - Preserves the trailing vector drawing or plain text **100% intact and unaltered**.
   * Final output line in the generated ASS dialogue:
     ```ass
     Dialogue: 0,0:00:01.00,0:00:03.00,Default,,0,0,0,,{\pos(640,360)\p1\1c&HFFFFFF&}m 0 0 l 50 0 l 25 -50
     ```

#### The Three Canonical Ways to Emit Tags + Shape/Text:
* **Method A (Full Line in `Result` $\to$ Wire to `Return`):**
  ```python
  tags = pos(syl.x, syl.y) + r"\p1" + c1(syl.color1)
  drawing = shape_star()
  result = f"{{{tags}}}{drawing}"
  # Connection: Result -> Return port (5) of System/Output
  ```
* **Method B (Modular Separation via `outputs` — Recommended):**
  ```python
  # Tags dispatched automatically via Loop Out
  result = pos(syl.x, syl.y) + r"\p1" + c1("&H00FFFF&") + fscxy(120)
  # Vector drawing dispatched via sub-output
  outputs['out1'] = shape_circle()
  # Connection: Out1 -> Return port (5) of System/Output
  ```
* **Method C (Direct Context Injection):**
  ```python
  context["return_raw"] = shape_heart()
  result = pos(syl.x, syl.y) + r"\p1" + c1("&H0000FF&")
  ```

### 2.3. Automatic Lexical Macros and Timing Shortcuts
Prior to bytecode compilation, the Pyxis engine applies regular expression preprocessing to support rapid shorthand notations:
* **Immediate Timing Multipliers:**
  * `2li` $\to$ `2 * li`
  * `-1.5lo` $\to$ `-1.5 * lo`
  * `3m1` $\to$ `3 * m1`
* **Frames and Ratios:**
  * `10f` $\to$ `(10 * frame_dur)` (automatically converts 10 video frames into milliseconds based on the active project FPS).
  * `1.5r` $\to$ `(1.5 * ratio)` (scales spatial magnitudes according to the active aspect ratio or module).

## 3. Injected Namespace and Typographic Context

The scripting runtime injects an extensive and immutable set of typographic, spatial, and kinematic metrics for the active unit:

### 3.1. Syllable Unit (`syl`)
Represents the current syllable in the karaoke timing sequence:

| Property | Type | Description |
| :--- | :--- | :--- |
| `syl.text` | `str` | Clean text of the syllable (stripped of karaoke and formatting tags). |
| `syl.text_stripped` | `str` | Syllable text without redundant whitespace or newline characters. |
| `syl.i` | `int` | 1-based index of the syllable within the line ($1 \le i \le n$). |
| `syl.n` | `int` | Total syllable count in the parent line. |
| `syl.duration` / `syl.dur` | `int` | Syllable duration in milliseconds ($\backslash k$ timing). |
| `syl.start_time` / `syl.st` | `int` | Absolute start timestamp in milliseconds. |
| `syl.end_time` / `syl.et` | `int` | Absolute end timestamp in milliseconds. |
| `syl.mid_time` | `float` | Absolute temporal midpoint ($\frac{st + et}{2}$). |
| `syl.syl_start` | `int` | Relative start offset in milliseconds from line start time. |
| `syl.syl_end` | `int` | Relative end offset in milliseconds from line start time. |
| `syl.x`, `syl.y` | `float` | Screen coordinates $(X, Y)$ computed from alignment and typographic baseline. |
| `syl.center`, `syl.middle` | `float` | Exact barycentric centre coordinates of the syllable box. |
| `syl.left`, `syl.right` | `float` | Horizontal bounding box boundaries. |
| `syl.top`, `syl.bottom` | `float` | Vertical bounding box boundaries. |
| `syl.width`, `syl.height` | `float` | Typographic dimensions computed via GDI/FreeType raster metrics. |
| `syl.color1` ... `syl.color4` | `str` | Base style ASS colours (`&HBBGGRR&`). |
| `syl.fontsize` | `float` | Nominal font size in points/pixels. |
| `syl.fontname` | `str` | Active font typeface family name. |
| `syl.bold`, `syl.italic` | `bool` | Bold and italic font style flags. |
| `syl.is_first`, `syl.is_last` | `bool` | `True` if the syllable is the initial or final unit in the line. |
| `syl.has_prev`, `syl.has_next` | `bool` | `True` if a neighbouring syllable precedes or succeeds the unit. |

### 3.2. Dialogue Line (`line` / `l`)
Represents the complete parent subtitle dialogue line from Aegisub:
* `line.text`: Full clean line text without override tags.
* `line.raw_text`: Original unparsed string containing all ASS override blocks.
* `line.start_time`, `line.end_time`, `line.duration`: Absolute dialogue timing timestamps (ms).
* `line.i`, `line.n`: 1-based sequential line index and total selected line count.
* `line.layer`: Dialogue line ASS integer layer.
* `line.style`: Name of the assigned Aegisub style descriptor.
* `line.actor`, `line.effect`: Metadata fields from the subtitle header.
* `line.margin_l`, `line.margin_r`, `line.margin_v`: Configured screen margins.
* `line.width`, `line.height`: Overall typographic dimensions of the rendered sentence.
* `line.center`, `line.middle`, `line.left`, `line.right`, `line.top`, `line.bottom`: Spatial boundary coordinates of the line.

### 3.3. Character (`char`) and Word (`word`)
When the iteration loop steps down to character or word granularities, `char` and `word` expose the identical set of metric and spatial properties as `syl`:
* Position: `char.x`, `char.y`, `char.center`, `char.middle`, `char.width`, `char.height`.
* Timing: `char.start_time`, `char.end_time`, `char.duration`, `char.char_start`, `char.char_end`.
* Indices: `char.i`, `char.n`, `char.is_first`, `char.is_last`.

### 3.4. Effect Frame (`fx`)
When kinematic systems or particle emitters reposition render coordinates away from the original layout:
* `fx.pos_x`, `fx.pos_y` (or `fx.x`, `fx.y`): Current origin coordinates of the emitted unit.
* `fx.org_x`, `fx.org_y`: Pivot coordinates for rotation and scaling ($\backslash org$).
* `fx.start_time`, `fx.end_time`, `fx.dur`: Active temporal window of the resulting dialogue line.
* `fx.i`, `fx.n`: Sequential particle index and total count within the emission cluster.

### 3.5. Ink Bounding Box (`ink`)
In contrast to nominal typographic boundaries (`syl.width`, `syl.height`), which include whitespace, ascender reserves, and tracking margins, `ink` describes the **actual geometric bounding box of the drawn vector contours**:
* `ink.width`, `ink.height`: True drawn width and height of the glyph outlines.
* `ink.center`, `ink.middle`: Geometric centroid of the rendered glyph shapes.
* `ink.left`, `ink.right`, `ink.top`, `ink.bottom`: Precise outer bounds of the vector path.

### 3.6. Neighbouring Units (`prev` and `next`)
Allows inspecting preceding or succeeding units to construct chain-reaction cascades or relative synchronisation offsets:
* `prev.text`, `prev.x`, `prev.y`, `prev.start_time`, `prev.duration`
* `next.text`, `next.x`, `next.y`, `next.start_time`, `next.duration`
* When at boundaries (e.g. initial or terminal syllables), `prev` and `next` return safe proxy objects with neutral default values (`0`, `""`) without throwing null reference exceptions (`NullReferenceException` or `AttributeError`).

### 3.7. Global Iterators and Slicing Variables
* `s_i`, `s_n`: Current piece index and total piece count generated by `Shape/Slicer`.
* `col`, `row`: Spatial column and row indices in 2D cellular meshes.
* `j`, `maxloop`: Iteration index and cycle count from `Loops/MaxLoop`.
* `a_i`, `a_n`: Item index and array length in array operations.
* `frame_dur` (alias `fd`): Duration in ms of a single video frame ($1000 / FPS$, typically $41.7\,\text{ms}$ at 23.976 fps).
* `fps`: Video frame rate frequency.

## 5. The Deterministic Stochastic Engine (`R` and the `by` Dispatcher)

Standard pseudo-random functions without a fixed contextual seed produce diverging values on each evaluation or frame, inducing spatial instability (*jittering*).

Pyxis resolves this behaviour by integrating a **deterministic pseudo-random engine whose seed is derived from the node topology and iteration indices**:

### 5.1. Standard Random Modes

* `R(min, max)`: Uniform deterministic integer or stepped float bounded by context.
* `Rs(min, max)`: **Symmetric bipolar random** generating values across $\pm [min, max]$.
* `Rc(min, max)` / `Rcs(min, max)`: Centesimal random with 2 decimal places.
* `Rd(min, max)` / `Rds(min, max)`: Decimal random with 1 decimal place.
* `Rm(min, max)` / `Rms(min, max)`: Millesimal random with 3 decimal places.
* `Rr(min, max)`: Random value scaled proportionally to video output resolution.
* `Rstep(min, max, step)`: Quantised random snapped to intervals of `step` (e.g. `Rstep(0, 360, 45)`).
* `R2d(min, max)`: Emits an independent coordinate pair `"X,Y"`.
* `Rbool(prob=50)`: Returns boolean `True` with the designated percentage probability ($0-100\%$).
* `Rcolor(c1, c2)`: Interpolates a random ASS colour along the hue gamut between two colours.
* `Re("optA, optB, optC")`: Randomly picks one item from a comma-delimited options list.

### 5.2. The Deterministic `by` Dispatcher

To guarantee that a random value is evaluated **strictly once per syllable, particle, or sub-loop iteration**, employ the following syntax:

$$\text{by}.\langle \text{iterator} \rangle.\langle \text{R\_mode} \rangle(\text{args})$$

**Practical Syntax Examples:**
```python
# A stable rotation angle per syllable (persists unchanged across nested loops)
ang = by.syl.R(-45, 45)

# A unique velocity offset per Slicer polygonal piece
vel_x = by.s_i.Rms(-150, 150)

# A distinct vertical jitter per MaxLoop clone index (j)
offset_y = by.j.Rs(20, 80)
```

## 7. Rules, Operational Boundaries, and Pitfalls

### ✅ Recommended Practices:
1. **Procedural Kinematics and Simulation:** Write custom physics models involving gravity acceleration, orbital trajectories, harmonic oscillation, or spring damping.
2. **Dynamic ASS Tag Synthesis:** Clean, transform, and compose tag strings using the native helpers (`merge_ass_tags`, `strip_tags`, `pos`, `move`).
3. **Multi-condition Formatting:** Branch styling decisions conditionally based on actor name, layer index, syllable timing, or upcoming dialogue gap.
4. **Data Fan-Out:** Assign values into `outputs['out1']`, `outputs['out2']`, etc., to broadcast coordinates or metrics across multiple graph branches simultaneously.
5. **State Retention:** Maintain incremental counters, trail emitters, or inter-line buffers using `remember()` and `recall()`.

### ❌ Absolute Prohibitions and Critical Constraints:
1. **Blocking Synchronous File I/O:**
   - *Forbidden:* Calling `open()` or disk inspection on every syllable or particle iteration. Cache file contents once via `recall()` or memory buffers.
2. **Mutating Engine Internals in Real Time:**
   - *Forbidden:* Attempting to overwrite internal dictionary bindings or host engine references (`context["_engine"] = None`). The context is designed for reading metrics and publishing tags.
3. **Injecting Mixed Types into Numeric Tags:**
   - *Avoid:* Injecting `None`, `nil`, or unvalidated strings into numeric ASS tags (e.g. `\pos(None, 20)`). Using Pyxis helper generators (`pos()`, `fscx()`) protects against syntax errors by sanitising arguments automatically.
4. **Unbounded Complexity inside Nested Loops:**
   - When a script sits inside multi-level iterators (`Slicer` $\times$ `MaxLoop`), code evaluates $P \times J$ times per syllable. Ensure computations maintain constant $\mathcal{O}(1)$ time complexity per iteration, avoiding `while` loops without a strict termination bound.
5. **Indentation Inconsistencies in Python:**
   - The integrated real-time linter validates scripts prior to evaluation. Irregular indentation produces immediate visual diagnostics in the node header.

## 8. Practical Production Code Recipes

### 8.1. Recipe A: Elastic Pop-In with Anticipation and Spring Dynamics (Python)

Replaces an entire graph chain of retimers, interpolators, and tag assemblers:
